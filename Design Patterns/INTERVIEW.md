# Design Patterns Interview Guide

## 🔥 Core Concept Questions

### 1. What are Design Patterns?
Reusable solutions to common software design problems.

### 2. Types of Design Patterns
- Creational
- Structural
- Behavioral

---

## 🧠 Creational Patterns

### Singleton
- What problem does it solve?
- How do you make it thread-safe?
- Difference between eager vs lazy initialization?

### Factory / Factory Method
- Difference between Simple Factory and Factory Method?
- When would you prefer Factory Method?

### Abstract Factory
- Difference between Factory Method and Abstract Factory?
- What is a “family of objects”?

### Builder
- When do you use Builder instead of constructor?
- How does it improve readability?

---

## 🏗 Structural Patterns

### Adapter
- When do you use Adapter?
- Difference between Adapter and Facade?

### Decorator
- How is Decorator different from inheritance?
- Real-world Java example?

### Facade
- What problem does Facade solve?
- Where is it used in microservices?

---

## 🔄 Behavioral Patterns

### Strategy
- When to use Strategy?
- How does it remove if-else?

### Observer
- How does Observer work?
- Real-world example?

### Command
- What problem does Command solve?
- Where is it used?

### Chain of Responsibility
- When should you use it?
- Example in backend systems?

### Template Method
- Difference between Template and Strategy?

### Iterator
- Why do we use Iterator?
- How does it hide internal structure?

---

## ⚔️ Important Comparisons

- Factory vs Abstract Factory
- Strategy vs Template Method
- Decorator vs Proxy vs Adapter
- Facade vs Adapter

---

## 🚀 Real-World Questions

1. Design a payment system using Strategy pattern
2. Design logging system using Singleton
3. Design UI themes using Abstract Factory
4. Implement middleware using Chain of Responsibility
5. Build configurable object using Builder

---

## 💡 Tips

- Always explain with example
- Focus on problem → solution mapping
- Mention pros/cons
- Relate to real backend systems

---

## 🎯 Final Advice

Interviewers care about:
- When to use pattern
- Why not use another pattern
- Real-world application
